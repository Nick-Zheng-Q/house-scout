# 候选与证据模板

一个具体单元及交易条件一条记录；不必为填满模板而猜测。

## 用户需求

- 租赁/购买；入住或交付时间；家庭/同住者：
- 城市、可接受区域、各常去目的地、到达时段、每周次数、可用交通工具与时间/交通预算：
- 户型、面积、楼层、电梯、同住者作息、在家办公、宠物、停车及其他硬条件/偏好：
- 重要生活设施（买菜、商圈、医疗、学校/托育、运动等）的类别与可接受到达时间：
- 月度预算、前期可动用现金、租期或持有计划：
- 仍需澄清的决定性问题：

## 候选

先做发现范围表：每个可接受区域分别写已查渠道、代表性搜索词、找到的具体单元、重复/下架情况和仍未查实线索。不要把同一套的多个挂牌算多个候选。

| 项目 | 内容 |
| --- | --- |
| 单元识别信息及位置 | 仅公开比较所需精度；房源编号、楼栋/楼层、面积口径 |
| 租赁/购买条件 | 价格、起租/交付日、期限或产权状态 |
| 发布者及公开联系入口 | 房东/运营方/经纪机构；授权是否核实 |
| 行动结论 | 值得看房 / 先补证据 / 暂不推荐，及原因 |
| 信息时点 | 发布/报价日、核查日、有效期 |
| 发布权限与交易状态 | 已核实/未知/资料冲突；具体依据 |

### 来源与冲突

通勤/配套另分：通用官方票价、发布者邻近时间估计、实际起终点与时段已执行路线。写“已查到票价/时间”必须说明是哪一种；商户具名＋平台估计分钟不等于独立核实可达。

逐条列链接或用户文件、日期、对应的单元与条件。另记证据是已打开单元详情、仅搜索文本、楼宇/房型页还是已失效报价，以及重定向结果。统计数量时说明包含哪类，不将不同口径的记录数相加当作可用房源。平台认证、照片和视频只能证明其标明范围；不能自动证明出租权、产权、现状或安全。不同发布者的面积、价格、押金、交付日或房型冲突时保留原说法并标**资料冲突**。

区分「房源已发布」「发布者称可交易」「产权/出租授权已核实」「现场可用」；四者不等同。聊天截图要记录取得日期和发送主体，不向外披露手机号等个人信息。

### 条件

| 决定性条件 | 硬条件/偏好 | 满足/不满足/未知/资料冲突 | 依据与日期 | 核实问题 |
| --- | --- | --- | --- | --- |

对每项硬条件注明证据是否直接覆盖。通勤要写起终点、方式和时段；学位/落户/贷款要写具体用户及房屋条件和当地正式条款，不以房源标签判断。

### 户型与居住适配

| 项目 | 目标单元的资料与来源 | 对该用户是否合适 | 待现场核实 |
| --- | --- | --- | --- |
| 户型、独立卧室/卫生间、厨房、客餐厅、阳台/储物 | | | |
| 建筑/套内/使用面积口径、楼层、电梯及无障碍路径 | | | |
| 朝向、采光、通风、噪声、家具/设备与交付状态 | | | |

明确写“适合什么生活方式/家庭规模、主要不便在哪里”，不要仅复述“精装两居”。若户型图或照片并非目标单元，标未知；样板间、同小区平均面积不能代替该套实际布局。

### 到用户常去地点

每个目的地都列至少一种用户确实可用的方式；有多种合理方式时分别列。用相同出行时段比较各房源，工作日高峰与周末/夜间可分开；时间为门到门，包含步行接驳、候车和换乘。费用按单程、往返和用户频率折成月度，列假设与算式。

| 目的地、出行频率 | 起终点/时段 | 方式与路线 | 门到门时间或区间 | 单程/往返/月费用 | 来源、查询日与不确定性 |
| --- | --- | --- | --- | --- | --- |

无确切楼栋入口、线路或票价时明确未知；驾车要分列停车、过路费与能源费，打车价格标查询时估价。不要以行政区中心到工作地的距离冒充实际通勤，也不要只报告最方便的目的地。

### 周边生活配套

只列与用户需求相关、可以具名和核查的设施及商圈；“附近有商场”不够。优先用实际步行路径时间，必要时补骑行或公交；营业/服务时段不明则不推定全天可用。

| 类别与具名地点/商圈 | 从房源到达方式、路线距离/时间 | 实际功能与相关性 | 来源、查询日和限制 |
| --- | --- | --- | --- |

可覆盖买菜/超市、餐饮、药店、医疗、公园/运动、学校/托育、快递、停车与商圈，但不为凑数量罗列。地图点位不证明商户仍营业；医院/学校附近不代表可用资格。说明缺失或未查实的重要类别及看房时需核实的路口、噪声或营业时间。

### 租赁费用与退出（租赁时）

| 项目 | 金额、单位、计费周期 | 必需/可选 | 付款时间 | 来源与未知 |
| --- | --- | --- | --- | --- |
| 月租及必需月费 | | | | |
| 前期不可退费用 | | | | |
| 可退押金 | | | | |
| 预付租金及其他预付款 | | | | |
| 条件性优惠 | 未确认前不抵减基础支出 | | | |

分别给出**已知月度小计**、**前期不可退费＋押金**及**签约/入住时实际需付现金**的逐项算式；付款时间未知的项目不要自行纳入或排除现金需求。说明退押金、维修、转租、续租、提前解约和退租清洁等条款。水电、网络、物业、停车、取暖、家具或中介费未核实时，不称费用已核全。

如用户考虑总月负担，另列“已知住房月费＋已知按频率折算的必要通勤费”，保留两部分明细；任一必需项未知时不能称总额。

如果优惠只适用于首月或指定期限，另列优惠期与之后的费用；入住时间不同可能改变付款周期与现金需求。

### 购买费用与风险（购买时）

分别列挂牌/报价、可证实的成交口径、预计首付、税费、交易服务费、贷款月供、物业和维护、装修/修缮、付款节点；为每项写依据和未知点。首付和月供只在融资方案有依据时估算，不能把贷款视作已获批。核查产权、共有权、抵押/限制、土地或房屋用途、交付、欠费、重大缺陷及合同解除条件；需要官方记录、验房或专业判断的事项明确写待核实。

定金/订金、意向金等付款的法律效果和退款条件不能凭名称推断；以具体合同和当地规则核查。已计入成交价的款项不要再次加总。融资金额或成交价未确认时仅给现金与月供情景，不判“已预算内”。

### 下一步

1. 问发布者 2—4 个会改变去留的问题，先核身份、授权、现价和可用状态。
2. 现场核查照片和地图无法证明的采光、噪声、气味、漏水、设施、楼宇维护和实际通勤。
3. 在付款或签约前核对书面条款、收款主体与正式记录；不要因限时催促跳过核查。
4. 如有身份/授权、收款账户或房屋可交易性疑点，明确暂停付款并列出解除疑点所需文件。
