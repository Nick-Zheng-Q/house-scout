# 从证据到推荐

用于完成候选比较；不要把“数据多”误当成“更合适”。

## 统一口径后再排顺序

1. **先淘汰明确违反硬条件的方案。** 每项硬条件写来源、日期和四态；`未知` 或 `资料冲突` 不是通过，列为先补证据。出行时间硬上限应看相应时段的门到门路线，不看地图直线距离。
2. **核实影响决策的事实。** 每套至少要有目标单元的户型/楼层/面积口径、实际可入住/交付时间、费用结构、到每个常去地点的可用方式/时间/费用、与用户相关的生活设施及商圈。缺一类时说明是资料缺口还是硬条件可能冲突，不能用“小区不错”补齐。
3. **同一口径比较。** 租房比较正常月度住房必要费、签约现金、租期与退出；购买比较相同价格及融资假设下的现金流情景；交通比较同一目的地、到达时段、出行频率和方式。必要时展示“住房已知月费＋通勤已知月费”，但水电/交通附加费等未知时不可称总额。通勤费用不应自动并入用户的房租上限，先确认预算范围。
4. **按用户偏好解释取舍。** 对剩余方案说明户型是否容得下实际生活、通勤节省多少时间/钱、买菜/药店/商圈是否方便、是否多付租金或牺牲退出弹性。用户没有指定偏好权重时，描述取舍并请其选择，不自创综合分或默认“最低租金优先”。
5. **给行动建议。** `值得看房` 表示无已知硬冲突且信息足够支持花时间现场确认，**不表示可签约**；`先补证据` 表示缺少会改变去留的决定性资料；`暂不推荐` 表示已知硬冲突或明显风险。每套优先列 2—4 个能改变结论的问题，以及现场需要走的路线、看房和配套核查点。

## 信息优先级

房源本身：优先目标单元的现行发布页、运营/业主/经纪书面条件及合同；跨发布者冲突要保留。出行：优先对目标时段可复核的地图路线和当地交通票价/时刻信息，标出门到门组成、动态价格和不确定性。配套：地图点位发现名称，再用商户/机构页面或现场核对营业及服务范围。政策、产权、资格：查当地正式渠道及具体房屋/用户情况。任一来源只能支持它实际显示的事实；房源页不能证明地铁票价，地图也不能证明产权或入学资格。

| 要回答的问题 | 优先查哪里 | 不能从什么直接推断 |
| --- | --- | --- |
| 现在有哪些具体房源、什么户型 | 当地房源平台/经纪挂牌、运营方或业主直供、开发商/公共住房正式入口；追到目标单元的现行页面和平面图 | 小区介绍、样板间、历史成交 |
| 实际租/售价、交付和合同 | 对应发布者当期报价、书面回复、合同；必要时当地交易/登记渠道 | 过期挂牌、另一个单元的优惠 |
| 到目的地多久、多少钱 | 指定日期时段的地图路线及交通运营方票价/时刻；停车、过路和动态打车费分查 | 直线距离、单独的车上时间、线路存在即全天可用 |
| 买菜、药店、商圈等是否好用 | 地图找具名点位和步行路径，再看商户/机构营业信息及现场 | 地图点位必然在营业、“配套成熟”宣传 |
| 产权、资格、学位或贷款 | 当地正式登记/主管部门规则、银行针对用户的文件及专业核验 | 平台标签、经纪口头保证 |

若地图或网页不可用，先利用用户材料；仍缺则明确“未核实”和需要的地址/时段/截图，不凭常识编造分钟、票价或商圈。若仅小区定位可用，说明楼栋入口造成的误差；不能把估算精度伪装为实测。

公共交通是硬要求时，步行模型更短也不等于满足；按[公交证据核查](transit-guide.md)，不能仅凭非时刻路线、其他日期参考、未核换乘或条件票价，把时间/费用硬条件标为已满足。
