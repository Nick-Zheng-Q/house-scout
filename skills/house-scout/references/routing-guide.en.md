# Routes, fares and amenities when a map UI is unavailable

**Required public transit:** use the [actual-time transit procedure](transit-guide.en.md). Walking models and amenity routes are not public-transport validation.

Use for each retained home, after [layout research](enrichment-guide.en.md). A Google directions URL failing in a text reader does **not** mean every route source failed. Work separately on coordinates, network routes, transit schedules/fares, and named businesses. Produce useful labeled estimates without pretending they are peak-time observations.

## Tool choice and access errors

| Capability available | Concrete action |
| --- | --- |
| Web search/read (`web.run`, `web__run`, or the host's web-search equivalent) | Search exact endpoints, local operator timetables/fare tables, Moovit/Rome2Rio route pages, official business locators. Open supporting results, not just snippets. These tools may not execute JavaScript/forms. |
| Authorized browser interaction, if available (browser tool **or existing host Playwright runtime**) | Use the browser tool's own instructions, or discover an existing runtime with the host dependency tool and follow [the Playwright procedure](transit-guide.en.md), to submit an origin, destination, local date/time and mode. Capture the **returned itinerary**, not the URL/form. A Codex UI tab opener is not a browser-control tool. Do not invent tool names or install a browser package automatically. |
| Authorized terminal/Python with HTTPS access | Run `scripts/query_routes.py` below to query documented public APIs. This is HTTP data retrieval, not browser automation. A sandbox DNS/network denial needs a scoped network approval; do not classify that as a provider outage. Do not bypass approval with another mechanism. |
| Existing authorized map/transport connector or API key | Use its documented routing/geocoding/POI methods and coordinate convention. Read secrets from approved configuration; never publish them in reports or command logs. If an API requires a key in its query string, redact that value from saved/displayed URLs and request metadata. No sign-up, payment or broad access grant is implied. |

A website's explicit block,401/403 or429 requires appropriate access/key, backoff or an independent source, not a changed user-agent/session to evade it. For a technical502/timeout, one bounded delayed retry is reasonable; then use another kind of source. Do not rotate mirrors to evade a limit. Missing a UI is not a reason to omit the read-only HTTP and timetable alternatives.

## Executable public-location helper

Standard library, Python3 on macOS/Linux; no packages, accounts or keys required by the helper. It queries **Photon** for candidate coordinates, **FOSSGIS OSRM's pedestrian backend** for walking, **Overpass** for small nearby grocery/pharmacy/mall selections, and the **VBB community REST service** for Berlin/Brandenburg transit. These donated/demo/community services are optional, not guaranteed infrastructure.

Read provider terms before use: [Photon demo/API](https://github.com/komoot/photon), [FOSSGIS policy](https://routing.openstreetmap.de/about.html), [Overpass policy](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html), [VBB wrapper docs](https://v6.vbb.transport.rest/api.html). The helper uses a shared single-process lock, at least1.2 seconds between requests, one-hour success caching and **no automatic retries**; all simultaneous agents on this machine share the pacing. Keep evaluation small, reuse results and do not deploy these public endpoints as a high-volume application backend. Provide OpenStreetMap attribution and a [fix-map link](https://www.openstreetmap.org/) with OSM-derived results. Public **Nominatim is not the default**: its [LLM/application-use policy](https://operations.osmfoundation.org/policies/nominatim/) requires a deliberate responsible choice and prohibits generic generated lookup services; do not silently substitute it.

Remote services log queries. Use only public fictional-test locations, or locations whose disclosure to the particular service is authorized. `--public-locations` acknowledges that requirement, not blanket consent for private home/work addresses. A public listing's address does not authorize uploading the user's private present address.

Run from the installed skill directory; put global flags **before** the subcommand. `--output` saves request URL, fetch timestamp, cache status, raw response and summary:

```sh
python3 scripts/query_routes.py --public-locations --output /tmp/place.json geocode "Old Street London" --tag railway:station
python3 scripts/query_routes.py --public-locations --output /tmp/walk.json walk --origin=51.5266,-0.0982 --destination=51.5257,-0.0875
python3 scripts/query_routes.py --public-locations --output /tmp/nearby.json pois --origin=51.5266,-0.0982 --radius 600
python3 scripts/query_routes.py --public-locations --output /tmp/berlin.json vbb --origin=52.507,13.322 --destination=52.525,13.369 --arrival=2026-12-01T09:00:00+01:00
```

These are public demonstration points/commands, not assumed home entrances or prevalidated itineraries. The `vbb` command is **only** for its coverage area, is a community wrapper rather than an official VBB API, and may fail or return a different date. Accept an itinerary only after checking returned endpoints, all legs, alerts and `requested_arrival_date_and_deadline_match`. Price absent from the result means unknown, not free.

### Coordinates and pedestrian routes

1. Read an exact public building address from the target offer, and resolve the destination's real entrance. Query Photon for candidates; verify city/country, house number, street and **object type**. The first “station” name might be a former station, bike dock or another city. `--tag railway:station` can narrow rail searches; it is not universal for every metro/bus stop. No candidate is automatically selected.
2. The helper inputs **WGS84 latitude,longitude**; Photon/OSRM GeoJSON coordinates are **longitude,latitude**. Do not swap these or mix GCJ-02/BD-09 from Chinese commercial maps with WGS84 without a verified conversion/source. A building centroid or street-only listing must be labeled approximate; do not invent a door number.
3. Run `walk` for outward and return, and separately for each chosen facility or transit access leg. It uses `/routed-foot/`, not a car router mislabeled walking. Inspect snapped waypoint locations/distances and step street names; unusual detours or inaccessible boundaries need checking.
4. Report its route distance and `model_minutes` as **an untimed pedestrian-network estimate**, with endpoint precision, query date and OSM attribution. It excludes indoor access, signals, live closures, crowding and unverified accessibility. Do not call it an executed09:00 itinerary. A valid walking route can still inform a45-minute preference comparison with those limitations stated; ticket fare is0 for that walk only, not all household travel.

## Transit without a working all-in-one planner

Use an actual API/HTML itinerary when available. Otherwise assemble a **sourced schedule estimate**: verified home→boarding access route + next applicable scheduled departure/wait + in-vehicle time + documented transfer walk/wait + alighting→destination route. Keep every component's source/date. Calculate departure backwards from required arrival; if the timetable/horizon does not cover that day, label the reference weekday/date and pending target-day confirmation. Do not call a static average a date-specific result. If a component is missing, report the known legs and a labeled partial estimate, not a fabricated total.

When presenting fare arithmetic use the actual sourced route/rider rule; paid alternatives and walking are separate scenarios. `check_commutes.py` can check entered estimates, but its arithmetic status does not certify source/route reliability. Explain estimated inputs rather than naming them verified.

## Nearby groceries, pharmacies, and commercial areas

1. Use `pois` for a **small bounded** OSM candidate search or web-search an official retailer's local store locator. If Overpass fails, query Photon for **one named business/address obtained from a real source**, not a city-wide sweep. A geocoder is not a complete shop directory.
2. Match the exact branch and address on the retailer/mall's official locator: examples include Tesco/Sainsbury's/Boots, Whole Foods/CVS, Woolworths/Coles/Chemist Warehouse, New World/Countdown/Woolworths NZ, FairPrice/Cold Storage/Guardian, AEON/matsukiyo, REWE/dm/Apotheke, Carrefour/pharmacie, Albert Heijn/Etos/apotheek. Choose actual local shops, not every brand. Search `"[brand/branch]" "[city]" official store locator`; mainland China/HK also use local mall/store pages and `超市/街市/药店`.
3. Route home→that branch on the **pedestrian network**. Report named branch, category/address, network distance/model minutes, endpoint precision and source links. POI straight-line distance is only for sorting and is never converted into walk minutes. If no independent business locator is found, keep the mapped place and route as a **mapped candidate**, not confirmed operating business.
4. Opening hours, pharmacist service and store existence are separately dated facts. OSM edit time is not last business verification. Do not infer prescription service, school rights or clinical access from a nearby map tag. For malls, say what functions it offers rather than counting icons.

## Minimum useful output and evidence

For each retained home deliver a supported route or labeled estimate, exact fare evidence or conditional fare scenario, and named daily facilities with separately supported access. Each result must identify whether it is a requested-time itinerary, an untimed pedestrian model, a timetable-based composition, a third-party reference estimate or a publisher proximity claim. These are not interchangeable. Save successful raw query artifacts and failures. Once a meaningful independent fallback has been tried, remaining gaps can stay explicit—but not all fields should be abandoned because one map UI fails.

## Public API policy versus a failed web page

For a documented public data API, read its publisher's API usage policy as well as the exact resource's access signals. [Overpass's manual](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html) explicitly supports manually submitted queries within limits; an indexing disallow for generic API paths alone is not a ban on that documented, low-volume user-directed use. Use small bounded queries, shared pacing, caching and attribution. This does not override explicit agent prohibitions, authentication, CAPTCHA, core403/429 or a denied endpoint; never switch hosts/identity to evade them.

Google's [documented public Maps directions URLs](https://developers.google.com/maps/documentation/urls/guide) use `https://www.google.com/maps/dir/?api=1&origin=...&destination=...&travelmode=transit` without an API key. Check current exact-path policy and the visible UI. A URL does not itself express/verify the required dated itinerary: set supported date/arrival controls, then inspect returned legs/fares. Bounded isolated-browser attempts in this review timed out; this remains a potential public channel, **not a demonstrated universal no-key fallback**. After an ordinary transport timeout, a single bounded HTTP compatibility check with unchanged honest identity may diagnose rendering; no stealth, security-disable, identity swap or retries after access denial.
