# Validation scope and release boundaries

Version 1.0.0 is a research skill with explicit limits, not a globally validated rental/purchase service. A platform/tool recipe does not verify arbitrary homes, routes, current prices or vacancy in that city. Research the actual listing, date and endpoints on every task.

As of 20 October 2026, **Munich, Eindhoven, Osaka and Boston—4 of 24 public commute cases—independently completed** the original 1 December 2026 outbound plan arriving before 09:00. The first two were prior independent results; the latter two followed this round's bilingual guidance repairs, with fresh agents reading no prior answers/response caches. All 22 previous incomplete cases were investigated again; 20 still lack complete original-date transit verification. October 21 reference services and development candidates are not counted as original-date passes. Amsterdam obtained a new railway-entrance model, but backing origin number74 conflicts with original198: its initial forward pass was downgraded after offline audit and is not counted.

“Complete” means a sourced **planned/modelled** original building/public-address entrance→original station public street entrance route: real service date, all required access/transfers and matched current adult fare. Disclose map alignment/snap offsets and timing assumptions. It is not a physical survey, private-flat threshold, train-platform deadline, accessibility/punctuality guarantee or fixed future price. An unknown return cannot become a verified return/monthly bill. None of these four cases guarantees an unchanged future fare; they do not prove arbitrary-address coverage.

Always separate:
- Complete original-date plan; complete other exact-date reference; station-pair schedules only; undated route/price references.
- No suitable transit returned, access restriction, missing house number, outside schedule horizon and missing connectors: these are different outcomes.
- Matched current tariff versus future pricing; outbound versus return. Unknown is not zero or assumed symmetry.

The original short one-north and Hong Kong Shatin cases returned no suitable transit; explain whether walking is preferable as a separate option, rather than manufacturing loops to increase passes. Street-only origins need an agreed address/public street point, not an unnoticed example-building substitution. Missing existing authorization does not authorize registration, billing or borrowed public-app credentials.

Not yet fully demonstrated: cross-market vacancy/budget/term-cleared homes, an independent complete purchase workflow, automatic triggering or with/without-skill effectiveness. Code/installation tests do not establish these behaviors. For restricted/uncovered cities return evidenced partial results and the exact missing prerequisite, not global-availability claims.

The host needs existing Python 3.9+ and authorized web/map/document capabilities; some network helpers support macOS/Linux only. This run executes on macOS/Python 3.12; Python 3.9 syntax checks do not establish minimum-version or Windows execution. No automatic browser installs, accounts, publisher contact, bookings, private-record submission, payments or signing. Respect existing-credential API permissions/billing and low-volume public-service policies. Documentation does not imply live validation or production-service guarantees.
